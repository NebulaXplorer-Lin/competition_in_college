# 竞赛雷达：架构、文件与使用说明

更新日期：2026-09-28。本文以当前源码为准。

项目目录：`D:\Study250711\coding_projects\campus_competetion`。

## 1. 项目定位

这是一个个人使用的校园比赛与活动清单网页。你维护信息，网页负责展示、搜索、筛选、按报名截止日期排序，并记录参加意向、收藏和备注。

目前是纯前端单页应用，没有登录、业务后端、云数据库、自动抓取或内置 AI。主要通过 CSV 维护信息。关闭网页后不会运行截止提醒，也没有邮件、微信或浏览器通知。

首次打开包含六条演示活动，日期随初始化时间生成，来源为示例链接，不能当作真实比赛通知。

## 2. 架构与数据流

```text
学校官网、通知、公众号等信息
        ↓ 人工整理 / 外部 AI 整理后核实
完整活动清单 CSV
        ↓ FileReader 读取 → CSV 解析 → 字段校验
React 的 events 活动数组
        ├─ 搜索、筛选、排序、统计 → 列表和详情抽屉
        ├─ 页面编辑 → 更新 events
        ├─ useEffect → localStorage 自动保存
        └─ CSV 导出 → 文件备份 / 外部更新 / 换设备迁移

再次打开同一浏览器、同一地址
        ↓
读取 localStorage 的 campus-events 键 → 恢复活动数组
```

### 页面与状态管理

- `useState` 保存活动、筛选条件、选中记录和导入提示。
- `useMemo` 计算标签、分类、统计数据和筛选列表。
- `useEffect` 在活动变化时保存到浏览器。
- `useRef` 引用隐藏的 CSV 文件选择控件。
- 没有独立路由或全局状态库，详情以同一页面上的抽屉展示。

### 数据实际存在哪里

比赛数据保存在浏览器 `localStorage` 的 `campus-events` 键中，格式为 JSON 数组。它不在项目文件夹中，也不会自动写回导入的 CSV。

同一浏览器配置、同一地址下刷新或重启服务通常能保留记录。更换浏览器、用户配置、协议、主机名或端口会使用独立存储。例如 `localhost:5174`、`127.0.0.1:5174`、`127.0.0.1:5173` 不共享数据。

仅移动代码目录、继续使用相同地址，不会直接移动或删除浏览器数据。清除站点数据会丢失记录，复制源码也不能备份个人活动，需另行导出。当前只保存活动数据，筛选条件和打开的详情在刷新后重置。

## 5. 启动与开发

### 日常启动

1. 进入项目目录，双击 `start.cmd`。
2. 保持终端开启，访问 [竞赛雷达](http://127.0.0.1:5174/)。脚本本身不会自动打开浏览器。
3. 使用结束后按 `Ctrl+C` 停止服务。停止服务不会主动清除本地活动。

服务绑定 `127.0.0.1:5174`，仅在本机访问。端口被占用时会报错，不会自动切换端口。

`start.cmd` 使用本电脑 `C:\Users\2007\.cache\codex-runtimes\...` 内的 Node.js 和 pnpm。换电脑后该路径可能不存在，需要配置 Node.js、pnpm 或调整脚本。

### 已配置 Node.js 和 pnpm 的环境

```powershell
cd D:\Study250711\coding_projects\campus_competetion
pnpm install --frozen-lockfile
pnpm dev
```

依赖已经安装时，日常只需执行 `pnpm dev`。

### 构建与预览

```powershell
pnpm build
pnpm preview
```

`build` 先运行 `tsc -b` 检查类型，再由 Vite 输出 `dist/`。`preview` 检查构建产物，访问地址以终端输出为准；若端口不同，该地址的数据存储也不同。

不要直接双击 `index.html` 运行应用。当前项目未部署到公网，构建也不会自动发布。

宽度不超过 680px 时，CSV 导入、导出和模板下载区域会隐藏。维护数据请使用电脑并将窗口拉宽。

## 7. 新增与更新比赛的推荐流程

### 首次建立清单

1. 点击“下载 CSV 模板”。
2. 使用表格软件或文本编辑器打开，将演示行替换为真实通知信息。
3. 每条比赛一行，填写唯一且稳定的 id，保留全部表头。
4. 保存为 UTF-8 编码、逗号分隔的 CSV，日期用 YYYY-MM-DD。
5. 点击“导入”，如出现错误，修正后重新选择文件；重复选同一文件无反应时，可刷新页面再选。
6. 核对数量、日期、标签、意向，再导出一份备份。

### 日常更新：先导出，再编辑完整清单，再导入

**导入会全量替换列表，不是追加或局部合并。**

网页原有 A、B、C，若导入文件只有 D，最终只剩 D。要新增 D，必须导入包含 A、B、C、D 的完整文件。

推荐步骤：

1. 点击“导出当前数据”，另存带日期的备份，例如 `比赛活动-2026-09-28-备份.csv`。
2. 在副本中追加新行或修改旧行。同一比赛保持 id 不变。
3. 保留其他比赛，以及已有意向、备注和标签。如果网页之后又有编辑，重新导出最新版本再整合。
4. 导入更新后的完整文件。
5. 核对记录数量和修改内容，再保存最新版备份。

导入后的意向、标签、备注等以 CSV 为准，会覆盖页面当前值。同 id 的旧收藏保留，新 id 默认不收藏，文件中未出现的旧记录会被移除。

只要存在校验错误，本次导入整体不生效，旧活动保持不变。

### 状态维护

- `status` 是生命周期：open 报名中、closed 报名结束、ended 已结束。
- `participation_decision` 是个人意向：yes 确定参加、maybe 不一定、no 确定不参加。
- 确定参加不等于已报名。目前无单独已报名字段，可在 notes 记录。
- 截止日期到了，不会自动改写 status，需手动维护。
- `last_verified` 是信息核实日期，页面改备注等操作不会自动更新它。

## 8. CSV 字段约定

保留以下 18 个字段。导入按表头名称映射，顺序可变化，但建议沿用导出文件顺序。

```csv
id,title,organizer,category,tags,description,source_url,registration_start,registration_deadline,event_start,event_end,location,eligibility,status,participation_decision,priority,notes,last_verified
```

| 字段 | 含义 | 填写约定 |
| --- | --- | --- |
| id | 稳定标识 | 必填、文件内唯一；如 csu-modeling-2026；更新同一比赛时保持不变 |
| title | 名称 | 必填 |
| organizer | 主办方 | 可空 |
| category | 分类 | 空值默认未分类 |
| tags | 标签 | 英文分号分隔，如 数学;团队;校级；可空、不重复 |
| description | 简介 | 可空 |
| source_url | 原始通知链接 | 可空；同文件非空链接不能重复 |
| registration_start | 报名开始日期 | 可空；非空用 YYYY-MM-DD |
| registration_deadline | 报名截止日期 | 可空，但建议填写以便排序与计算剩余天数 |
| event_start | 活动开始日期 | 可空；非空用 YYYY-MM-DD |
| event_end | 活动结束日期 | 可空；非空用 YYYY-MM-DD |
| location | 地点或线上方式 | 可空 |
| eligibility | 参赛资格 | 可空 |
| status | 生命周期 | open / closed / ended；空值默认 open |
| participation_decision | 意向 | 必须 yes / maybe / no；空值报错，不确定填 maybe |
| priority | 优先级 | 建议高、中、低；空值默认中；只有高会显示高优先级标识 |
| notes | 个人备注 | 材料、组队、报名情况、待核实问题等 |
| last_verified | 核实日期 | 可空；非空用 YYYY-MM-DD |

全部表头必须存在，但不是全部值必填。没有时分字段，截止时间以日期为单位。

含英文逗号、换行或双引号的字段应整体用双引号包裹，内部双引号写成两个双引号。网页导出和表格软件保存 CSV 可自动处理。不要仅把 xlsx 改扩展名后导入。

当前校验包括缺失表头、空 id/标题、枚举、日期格式、重复标签、文件内重复 id 和非空来源链接。日期只检查格式，不完整检查真实日期或起止先后关系，仍需人工核对。空标签会被过滤，不会报错。

## 9. 用外部 AI 整理更新

网页不调用 AI。可以把导出的完整清单与新通知交给外部 AI，核实结果后再导入。可复用下面的提示词：

```text
请根据我提供的比赛通知，更新附件中的校园比赛 CSV。

1. 输出完整清单，保留未涉及的旧记录，不要只输出变动行。
2. 保留全部 18 个表头，使用 UTF-8 逗号分隔 CSV。
3. 同一比赛保留原 id，新比赛使用唯一 id，避免重复收录。
4. 保留已有参加意向、备注和个人标签，除非我要求修改。
5. 新比赛意向不确定填 maybe；意向只允许 yes、no、maybe。
6. status 只允许 open、closed、ended，不要和参加意向混淆。
7. 标签用英文分号分隔并去重，日期使用 YYYY-MM-DD。
8. 不编造日期、来源、资格或主办方；未知字段留空，在 notes 写明待核实。
9. last_verified 只写实际核实该条信息的日期，不要批量伪造更新日期。
10. 正确转义逗号、换行和双引号，检查重复 id 和非空 source_url。
11. 另列新增、修改、删除记录和待确认问题，不要把说明文字混入 CSV。
```

如果一个通知链接对应多个比赛，当前重复来源校验可能阻止导入，应人工确认记录方式，不要为了通过校验编造不同链接。

## 10. 备份与迁移

- 批量更新或删除前导出 CSV，保留日期版本。
- 换电脑时迁移代码并安装依赖，再在新浏览器导入清单。
- CSV 没有 starred 收藏字段，因此不是全部界面状态的完整备份。跨浏览器迁移后需要重新收藏；同浏览器导入时仅同 id 的收藏会被保留。
- 旧 5173 地址的数据不会自动出现在 5174。如果原地址仍能使用这套页面，可以先导出，再在新地址导入。移动源码不能读取旧地址的存储。

## 11. 当前限制与验证情况

以下是代码目前的实际边界，尚未补齐：

- 无自动采集、云同步、通知、完整新建表单；筛选不持久化，标签筛选单选。
- 已过期记录不自动归档，可能排在列表前面。
- “即将截止”统计只计入 open 活动，但该视图列表未使用同样限制；可再选报名中，使范围一致。
- 日期计算没有定时器驱动，跨日长时间打开后建议刷新；顶部英文星期固定显示 SATURDAY。
- “已自动保存”是固定提示，未反馈存储失败，不能替代文件备份。
- 窄屏隐藏 CSV 操作入口，数据维护主要在宽屏进行。

后续可以优先完善完整活动表单、导入预览与合并模式、包含收藏的完整备份、严格日期校验。
