# 比赛收集与 CSV 工作流使用指南

更新日期：2026-10-04。

这套工作流在 Codex 中整理比赛信息：需要检索时交给轻量子代理，先展示来源和预览，确认后生成 CSV，再由你手动导入竞赛雷达。网页本身不调用 AI。

## 1. 日常使用：你只需提供材料、确认、导入

1. 在 Codex 中打开本项目。
2. 网页已有活动时，先点击“导出当前数据”，把最新完整 CSV 附在聊天中；文件夹中的演示数据不能替代它。
3. 提供比赛名称、官方通知链接或正文，说明年份、学校和目标阶段。
4. 调用 `$campus-event-csv`，等待预览。检查截止时间、资格、年份、报名阶段及来源。
5. 回复“全部确认”“只录入第 1、3 项”，或指出具体修改。
6. 下载生成的 CSV，手动导入网页，核对数量及修改内容，再导出备份。

**导入会全量替换网页清单。**已有 A、B、C 时，新增 D 应使用包含 A、B、C、D 的合并文件。只导入 D 会移除其他记录。

通常不需要自己写 JSON 或运行 Python；这些交给 Codex 完成。第 5 节的命令用于人工检查或排错。

## 2. 可以直接复制的请求

### 首次收集，没有旧清单

```text
使用 $campus-event-csv 整理以下比赛。
学校：中南大学；目标年份：2026；目标阶段：校内报名。
比赛：［填入名称或官方通知链接］。
这是首次建立清单，没有需要保留的旧活动。
先展示字段、来源、缺失项和截止时间，等我确认后生成 CSV。
```

### 在现有清单中新增

```text
使用 $campus-event-csv，在附件的最新完整 CSV 中新增这些比赛：［名称或链接］。
目标年份为2026，优先核实中南大学校内报名通知。
保留原活动及个人意向、标签、优先级和备注。
生成完整合并清单，先给预览及变更，等我确认。
```

### 更新一项活动

```text
使用 $campus-event-csv，根据这份新通知更新附件清单中的［比赛名称及阶段］。
只更新本次确认的日期和来源信息，保留原 ID 和个人字段。
如果是延期或不同阶段，请说明差异，先展示修改前后的值。
```

### 已有通知正文

```text
使用 $campus-event-csv，提取下面通知中的活动信息。
优先使用现有材料，只搜索影响身份、报名或资格判断的缺失信息。
目标学校、年份和阶段是：［填写］。
通知正文：［粘贴］。
```

用户提供的正文会标注为用户材料；只有实际读取外部原始来源，才会标为联网核验。未指定目标年份且无法确认时，Codex 会先澄清。

## 3. 如何使用订阅额度和轻量子代理

本机已同步安装个人 skill。其他电脑可直接要求 Codex 使用项目文件 [SKILL.md](../skills/campus-event-csv/SKILL.md)，也可以将整个 `skills/campus-event-csv/` 目录安装至个人 `~/.codex/skills/` 后使用 `$campus-event-csv`。

使用订阅访问时，在 Codex 中以 ChatGPT 账户登录。若使用 CLI，可检查：

```powershell
codex login status
```

应显示 `Logged in using ChatGPT`。未登录时执行 `codex login` 完成 ChatGPT 登录；API key 登录属于另一种计费方式。本工作流不要求配置模型或搜索的付费 API。

| 情况 | 当前处理方式 |
| --- | --- |
| 短且完整的通知 | 主代理直接提取，不创建子代理 |
| 需要搜索或读取多份通知 | 默认一批一个 `gpt-6-luna`、`low` 子代理 |
| 需要判断日期冲突或报名阶段 | 主代理查看相关证据，必要时安排一次定向补查 |
| 日期、重复记录、CSV 格式检查 | 本地 Python 脚本，不调用模型 |

项目配置为 [.codex/agents/event_researcher.toml](../.codex/agents/event_researcher.toml)。客户端支持按名称选择时使用 `event_researcher`；否则 skill 要求创建时显式指定模型和推理强度，并在支持时使用 `fork_turns=none`。核对实际创建参数，不能只看子代理的名字或自述。

模型需在当前账户和客户端可用。不可用时工作流报告限制，不自动切换更贵模型或付费 API。首次配置后若客户端尚未识别项目 agent，可重新打开项目聊天；skill 的显式参数方式仍需客户端支持。

主代理与子代理共享账户额度，子代理没有独立免费额度。当前没有自动搜索定时任务或持久缓存，也没有测量实际节省比例。

## 4. 检索范围、返回结果和确认

初次每项最多 **2 条搜索查询、3 份原始资料**，附件和已提供通知也计入资料数。失败重试也计入次数；有充分关键证据就提前停止，不为了写长简介或补标签继续搜索。

对同一项，主代理最多再安排一次定向补查：**1 条查询、1 份新增资料**。仍无法解决时，返回缺失或冲突；无法识别的活动暂缓。以上是代理遵循的流程规则，计数不是工具硬限额，也不是账单预算。

子代理返回字段、短原文证据、来源、缺失项及查询计数，避免把整页正文传回主聊天。格式见 [研究结果 schema](../skills/campus-event-csv/references/research-result.schema.json)；具体调度规则见 [检索工作流](../skills/campus-event-csv/references/research-workflow.md)。

确认时重点看：

- 是不是正确的年份和届次，届次未知是否明确留空。
- 截止时间属于校内报名、选拔还是全国赛事。
- 资格是否保留年级、学历、组队人数和排除条件。
- 缺失信息是否明确标注，原始来源是否可核对。
- 合并清单是否保留原 ID、个人字段和其他活动。

CSV 日期精确到天，具体截止时刻放在备注。`status=open` 表示按日期自动判断，网页可能显示尚未开始、报名中或时间待定；`unknown/upcoming` 是显示状态，不能写入 CSV。

## 5. 手动校验或生成 CSV

安装 Python 3；工具只使用标准库。以下命令在仓库根目录运行，文件名替换成实际文件；路径含空格时加引号。

### 校验已有清单

```powershell
python skills/campus-event-csv/scripts/csv_tools.py validate "用户导出的完整清单.csv"
```

成功会返回 `valid: true` 和记录数。失败会列出表头、列数、重复、日期或枚举问题，不修改输入文件。

### 确认后生成完整合并清单

```powershell
python skills/campus-event-csv/scripts/csv_tools.py generate --input "已确认记录.json" --baseline "用户导出的完整清单.csv" --output "新的合并清单.csv"
python skills/campus-event-csv/scripts/csv_tools.py validate "新的合并清单.csv"
```

首次或仅新增时省略 `--baseline`，且不能包含旧记录更新。输出文件必须尚不存在；换一个文件名保留旧版本。

### 已确认 JSON 的结构

以下只是格式示例，不是真实比赛数据。实际使用前须完成预览确认；`confirmed=true` 不能替代确认。

```json
{
  "confirmed": true,
  "records": [
    {
      "title": "示例比赛2026（校内选拔）",
      "status": "open",
      "tags": ["编程", "团队"],
      "notes": "格式示例，日期和来源待核实"
    }
  ],
  "updates": [
    {
      "id": "旧CSV中已存在的ID",
      "fields": {
        "registration_deadline": "2026-10-22"
      }
    }
  ]
}
```

`records` 只新增，`updates` 按旧 ID 只修改列出的字段。其他旧字段保留，没有删除入口；更新备注时提交保留原备注后的完整内容。

新 ID 可以省略，由标题和来源生成稳定 UUID；不同届次或阶段应在标题中区分。新记录的参加意向默认 `maybe`、优先级“中”、分类“未分类”，状态必须显式填写。未知信息可以为空，标签可用字符串数组或英文分号分隔的字符串。

工具生成 UTF-8 BOM、CRLF 的 18 列 CSV，并回读校验。它不验证来源真实性或浏览器现有数据，也不自动导入网页。完整字段说明见 [CSV 约定](../skills/campus-event-csv/references/csv-contract.md)。

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| `$campus-event-csv` 没被识别 | 明确引用项目 `skills/campus-event-csv/SKILL.md`；检查个人安装目录或重新打开聊天 |
| 没出现子代理 | 短且完整的通知会直接处理；需要检索时检查实际委派及模型参数 |
| 模型不可用 | 查看限制，再明确选择账户可用的方案；不会自动增加 API 支出 |
| 搜索用完但某些字段仍缺失 | 先看已有结果和待核实项，再决定是否授权扩大范围 |
| 提示需要 baseline | 从网页导出最新完整 CSV；项目文件夹没有浏览器现有清单 |
| 提示输出文件已存在 | 使用新的输出文件名，不覆盖备份 |
| 同一通知覆盖多项比赛，来源重复 | 查看是否有独立通知；没有时确认主 URL 放在哪条记录，其余来源写备注，不编造 URL |
| 更新网页后合并文件过时 | 重新导出最新清单并重新核对受影响的变更 |
| Python 命令不可用 | 配置 Python 或让 Codex 使用环境中已有解释器；不需要安装 CSV 第三方包 |

## 7. 维护与验证

项目 `skills/campus-event-csv/` 和个人安装副本不会自动同步。修改规则或脚本后同步整个 skill；项目级 agent 配置留在项目的 `.codex/agents/`。

本地研究材料、确认 JSON 和生成文件可以放在 `outputs/`，已被 Git 忽略；个人清单不需要提交到代码仓库。

可运行以下测试（日期测试需要支持直接执行 TypeScript 的 Node.js，本机使用 Node.js 24）：

```powershell
python -m unittest discover -s tests -p "test_campus_csv_tools.py" -v
node --test tests/eventDates.test.ts
```

当前验证覆盖 8 项 CSV 工具测试、4 项日期测试，并已用轻量子代理完成离线提取试运行。离线样例不能证明外部网站可访问、真实搜索准确率或具体节省额度；实际使用时仍需核对来源和账户用量。
